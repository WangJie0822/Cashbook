# 搜索页关键词汇总与分类净额分布设计

整体方案于 2026-10-31 获用户确认（回复“ok”）；在当前会话实施，验证后仅本地提交。

## 目标与用户已确定的规则

- 关键词搜索增加总笔数、收入、支出、结余。
- 关键词搜索与筛选都增加分类分布饼图。
- 保留关键词和筛选互斥；不把已应用的筛选条件叠加到关键词搜索。
- 收入、支出、转账放在同一张图，不分三个页签。
- 饼图采用净收支口径；转账本金不计入，只计手续费减优惠。
- 负净额按绝对值计算扇区占比，图例及金额明细保留负号。用户已确认这一表示方法。
- 本文其余界面与技术细节由 Codex 提出，已随整体方案确认。

## 当前依据与问题

- `feature/records/src/main/kotlin/cn/wj/android/cashbook/feature/records/viewmodel/SearchViewModel.kt#startQuery` 只在 Filter 模式启动汇总；Keyword 模式隐藏汇总。
- `feature/records/src/main/kotlin/cn/wj/android/cashbook/feature/records/screen/SearchScreen.kt#SearchScreen` 只在 filtering 条件成立时显示汇总卡。
- `core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/dao/RecordDao.kt#queryRecordByKeyword` 在当前账本内按备注 LIKE 或数值关键词的 amount/final_amount 精确匹配；按 record_time DESC 排序。
- `core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/repository/impl/RecordRepositoryImpl.kt#queryPagingRecordListByKeyword` 使用现有 toBigDecimalOrNull/toAmountCent 数值转换。新的统计必须与该路径逐项一致，保留通配符、转义、空白、数字哨兵及排序现状。
- `core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/repository/impl/RecordFilterSqlBuilder.kt#build` 已有完整筛选、EXISTS 标签去重和净额汇总。汇总只需金额与分类信息，不需要把所有关系和图片转换为 UI 列表。
- `core/design/src/main/kotlin/cn/wj/android/cashbook/core/design/component/PieChart.kt#CbPieChart` 已提供扇区点击、选中及自定义间距。默认 2 度间距会把很小扇区扣为零；本页调用使用 0 度间距，不改共享组件默认值。
- `feature/records/src/main/kotlin/cn/wj/android/cashbook/feature/records/view/PieChart.kt#AnalyticsPieChart` 会过滤占比不超过 3% 的分类，且 Analytics 的转账金额采用不同口径，因此不能直接照用该封装及其金额用例。

## 数据范围与金额契约

统计针对当前查询的全部匹配记录，独立于分页大小、已加载页数和滚动位置。当前账本是查询上下文的一部分。

| 记录 | 汇总收入贡献 | 汇总支出贡献 | 分类净额 |
| --- | --- | --- | --- |
| 收入，包括退款、报销收入 | finalAmount | 0 | finalAmount |
| 支出 | 0 | finalAmount | finalAmount |
| 转账 | 0 | charge − concessions | charge − concessions |
| 平账 | 0 | 0 | 不进入分布 |

总笔数仍包含匹配的平账、零贡献记录。结余仍为收入减支出，不将本金或报销实收金额重新加回。

分类分布先按“收支类型 + 当前一级分类 ID”汇总有符号净额，再取每个分类净额的绝对值计算占比：

`分类占比 = abs(该分类净额) / sum(abs(所有分类净额))`。

不能先对每条记录取绝对值。例如同一转账分类 +5 与 −3 的分类净额是 +2，占比基数中的贡献是 2；+3 与 −3 抵消为 0。负值不截断，不改成正值展示，也不偷偷归入收入类型。收入、支出、转账的业务归属保持原分类。

只有净额不为零的组产生扇区；零净额组保留在可展开的分类明细中。所有组净额为零时显示“暂无可绘制的净收支”，不画虚构的整圆或 NaN 百分比。负值独占时允许图中 100% 扇区，金额仍带负号。

金额在存储和求和链路保持 Long 分，绘图比例才转换为浮点数。绝对值及占比基数的极值溢出不得静默回绕，具体精确计算实现交给实施计划，须有极值守卫。

## 分类分组与异常元数据

- 一级分类直接记账与它当前的二级分类合并至一级分类。
- 父级有效必须同时满足存在、为一级分类、收支类型与子项一致；不符合则按下述失效父级规则回退自身。
- 名称不作键；跨收支类型同名、同类型下不同 ID 同名不得混在一起。
- 图例显示“支出 · 餐饮”“收入 · 工资”等业务上下文，金额、百分比、颜色及点击高亮对应同一组。
- 二级分类父级失效或缺失但自身分类有效时，以自身作为独立分组显示真实名称，不让有效净额在图中消失，不猜测或修复原父级。
- 无法识别类型的历史记录仍按现有汇总 SQL 的贡献规则处理；不能为了画图凭名称推断收支类型。测试须比较分类分组总贡献与现有汇总规则的结果。
- 按分类净额绝对值降序排序，平局采用稳定 ID 次序；分类改名、改层级后按最新元数据刷新。

## 页面设计

顺序为搜索栏、当前查询条件摘要、收支汇总、分类分布、账单列表。关键词与筛选两种模式共用同一套统计展示。

- 初始未查询状态继续显示原搜索历史，不主动查询全账本，也不显示零统计卡。
- 汇总沿用现有四项数据和金额格式。关键词模式同样解释净额与账单显示金额的差别，不改其它页面的列表默认行为。
- 分类分布默认展开，提供折叠按钮。折叠不清除查询、数据或选中分类，不改变列表结果。
- 复用 CbPieChart，直接传入全部非零分类，关闭密集外部标记线，使用下方图例保证可读性；没有 3% 数据过滤。
- 圆心默认说明“占比基数”并展示分类净额绝对值之和，不把这一数字标成结余。选中分类后显示完整分类名、有符号净额和百分比；再次点击取消选中。
- 图例默认显示前 5 个分类，提供“展开全部/收起”；折叠仅影响图例行数，所有扇区始终参与占比。分类很多时随主页面滚动，不嵌套抢占纵向滚动。
- 全量分类明细包括零净额分类。占比说明注明“按各分类净额绝对值计算，金额保留正负”；零值显示 0%，极小正占比避免显示为误导性的 0%。
- 点击扇区或图例只改变高亮，不自动增加筛选、跳转全账本统计或修改当前记录列表；本轮不增加二级钻取和图表导出。
- 小屏保留统计可读性及可折叠分布；平板/折叠屏按可用宽度布局，不靠固定屏幕像素。

## 数据路径提案与一致性

- 保留现有 feature → domain → data → database 分层，无新依赖、无 schema 迁移。
- 为关键词查询构造不可变上下文，至少固定 bookId、原始关键词及由现有转换得到的金额参数；分页和聚合使用同一上下文，防止页加载途中切账本造成串账。
- 保持原关键词 SQL 的匹配与排序。抽取/扩展匹配条件时，真实旧 DAO 与新路径必须用同一数据逐条对照，不能只比较两个复制的新实现。
- 筛选统计扩展到分类聚合时，复用同一匹配集合及绑定参数；标签使用 EXISTS 或等价去重策略，重合分类和多标签不能放大金额、笔数。
- 汇总与分类聚合在同一个数据库快照中取得，作为一个统计结果原子发布；不得把旧汇总和新图表用两个独立 Flow 直接拼在一起。
- 数据库侧聚合，返回汇总和分类行；不加载所有图片、资产、关联记录来计算图表。不用 Int.MAX_VALUE 拉全量列表，也不按已加载页汇总。
- 具体 DAO/API 命名、一次查询或事务快照方案、SQL 形态交给实施计划；实现必须提供统计同快照的实证，遵守绑定参数预算。
- 复用查询版本和 attempt 机制，切关键词、切筛选、切账本、重试、数据失效时取消旧工作；旧响应不得覆盖新查询统计。
- 金额、分类层级、名称、标签关系或账本记录变动后，列表与统计应按相关数据库失效机制刷新。元数据变更不沿用失效高亮；可按真实组键保留仍有效的选中项。
- 统计加载中显示骨架或进度，隐藏旧查询统计；统计失败显示可重试错误，保留仍可用的列表，不伪装为 0。列表失败沿用现有列表错误状态。
- 无匹配结果显示 0 笔、零收支和分布空态；不得混同“有匹配但净额都为零”。

## 影响范围与边界

预期影响 records 搜索页及其状态/截图、domain 的关键词用例、data 的查询契约/实现/测试替身、database 的只读聚合查询/结果类型、model 的统计模型和计算测试。API 若新增显式 bookId，检查所有调用处并保持其它入口行为。

不修改关键词含义、筛选互斥规则、退款报销吸收算法、金额存储、首页/Analytics/Budget 的统计口径、分类编辑修复、CI、依赖版本或 release。已有分类修复分支仍仅本地，本分支从当前远端 main 派生，不夹带该修复。

整体设计已确认，按实施计划执行；实现仅本地提交，推送另行授权。遵守用户本会话不归档选择，不写 Vault 或自动归档登记。
