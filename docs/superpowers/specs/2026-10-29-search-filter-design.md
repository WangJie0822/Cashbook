# 搜索页组合筛选与收支统计设计

创建日期：2026-10-29；评审、grilling 与全文确认：2026-10-30。状态：用户已确认完整设计，进入实施计划；尚未修改产品代码。

## 目的与已确认范围

用户希望查看同一标签下不同收支类型、指定日期范围内多个分类的整体收支，避免只能逐项查看、再自行相加。

对话已确认：

- 在搜索界面添加筛选按钮，通过侧栏设置筛选。
- 有关键字时独立使用原搜索逻辑，不叠加筛选。
- 无关键字时支持时间、收支类型、分类、标签组合筛选，分类与标签可多选。
- 多选标签匹配任意一个，同一账单不重复统计。
- 日期只需一段起止日期。
- 仅查询当前账本。
- 分类多时采用分层选择：收支类型页签、一级分类导航、二级分类选择、名称搜索、已选摘要与跨分类多选。用户已确认第二版交互草图。
- 转账本金不计入收支；转账的手续费与优惠计入收支，按首页的“手续费减优惠计入支出”口径。
- 标签显示全部，包括已隐藏标签，并标记隐藏状态，便于筛选历史账单。
- grilling 已确认：沿用净自付统计，允许后续关联报销／退款改变历史日期范围的金额；同组取任一、跨组取交集；清空关键字恢复筛选；同一搜索页返回时保留条件与位置，真正退出后重进重置；首次进入等待显式应用筛选。
- grilling 已确认：整组分类选择自动覆盖以后新增的子分类；取消个别项表达“整组减去例外”；外层收支类型限制可选分类，变更后移除不兼容分类并提示；账单主金额保持原显示，差异行额外说明统计计入额。

目标是列表、命中笔数、收入、支出、结余始终对应同一组筛选条件。非目标：跨账本汇总、多段不连续日期、关键字与筛选叠加、保存筛选模板、导出结果、修改既有首页或分类统计规则。

## 界面与操作

### 搜索页

- 搜索栏右侧放置筛选按钮；筛选应用后显示激活标记。
- 筛选模式下，搜索栏下方显示条件摘要、总笔数、收入、支出、结余，再显示账单列表。
- 条件摘要对大量分类只展示少量名称与总项数，避免撑满页面。
- 保留账单点击详情、编辑、资产跳转与列表现有样式。
- 仅在筛选模式、账单主金额与统计贡献不同的行增加“统计计入：收入／支出 ¥X”等说明；平账差异行说明不计收支。转账显示本金但只统计手续费减优惠；关联报销／退款收入显示实收额但统计净溢出。主金额规则复用现有 `LauncherContentScreen.kt` 的 `RecordListItem`，不改变首页、关键字搜索或其它调用方默认显示。
- 手机、平板、折叠屏均需可操作；侧栏宽度和分层选择区按可用窗口适配，不使用固定像素锁定布局。

### 筛选侧栏

顺序：时间、收支类型、分类入口、标签，底部固定“重置”和“完成”。

- 时间：不限时间或一段起止日期，包含起始日与结束日。可提供本月、上月、今年快捷选项；月周期遵循现有月起始日设置，不能另造自然月口径。
- 收支类型：支出、收入、转账，可多选；未选择任何类型表示不限。
- 收支类型为不限时，全部类型的分类均可选择；限定类型后，仅允许选择这些类型的分类。变更类型只移除新允许范围之外的已选分类，并提示被移除项；回到不限不会额外删除仍兼容的选择。
- 分类：紧凑入口展示已选项数和少量名称，点击进入侧栏内部的分层选择页。
- 标签：多选，未选择表示不限标签；显示全部标签，已隐藏项标记“已隐藏”，仍可选择、移除与匹配历史账单。隐藏不是删除，已选标签后来被隐藏时保留并继续生效。
- “重置”只清空侧栏草稿，不立即刷新结果；按“完成”应用草稿。
- 关闭侧栏、点击遮罩或返回，放弃尚未应用的侧栏修改，保持当前结果。
- 日期不完整或结束早于开始时，显示错误并禁止完成。
- 初次打开的筛选草稿为不限时间、不限类型、不限分类、不限标签；演示草图中的旅行标签与日期不是产品默认值。

### 分类分层选择页

- 顶部支出／收入／转账页签，仅展示或启用外层允许的类型；页签只切换分类浏览，不额外修改外层收支类型。
- 左侧一级分类，右侧当前一级分类的二级项；无子分类时直接选择该一级分类。
- 有子分类的一级分类提供“全选本组”，动态覆盖父分类直接记账及其二级分类，包含选择后新增的子分类；也可以单独选择父分类直接记账项，界面采用“仅一级分类”并以真实父分类名称说明，不创造新的数据库分类。
- 父组显示未选、部分选中、全选状态及已选数量；整组全选后仍能取消个别子项。
- 整组选中后取消某个子项，保留“父组减去排除项”的动态意图；新子分类仍自动纳入。新增、移入或移出该父组的分类按当前层级重新匹配；单独勾选的精确分类则跟随其真实 ID。不能把动态整组压平成选择当时的子 ID 快照。
- 选择以真实分类 ID 去重，显示名称不作为筛选键；跨类型同名分类不会混淆。
- 名称搜索只检索当前浏览收支类型的一级与二级分类，不调用账单关键字搜索；匹配子项时展示其父级上下文。
- 切换收支类型、一级分类或搜索文本不会清空已选分类。
- 底部已选区支持查看及移除跨组选择；从父组或子项重复选择同一 ID 不重复计数。
- “选好了”合入侧栏草稿；返回则放弃分类选择页本次改动。只有外层“完成”才更新结果。
- 正常交互通过类型联动避免不兼容组合；恢复状态或外部数据变化造成的冲突须提示并保留约束，不自动扩大查询范围。用户主动变更外层类型时按已确认联动规则清理不兼容项，两种触发不能混为一谈。

## 筛选语义与模式切换

### 条件关系

总条件为：当前账本 AND 日期范围 AND 收支类型集合 AND 分类 ID 集合 AND 标签集合。

同一组类型或分类取任一；标签按用户要求取任一。分类条件保留精确 ID、动态父组 ID 与排除 ID 三部分；父组表示当前自身及当前子分类，排除项不匹配。空组表示不限，但“所选 ID 已全部失效”不等于空组，不能退化为查询全部。

先形成唯一账单 ID 集合，再分页、计数或汇总。带多个命中标签的账单只出现一次。不得先取一页账单再在内存筛选；汇总不得仅统计已加载的页面。

### 三种状态

| 状态 | 列表与统计 | 进入方式 |
| --- | --- | --- |
| 初始状态 | 保持原搜索页未搜索状态；不自动扫描全账本，不显示零值统计卡 | 首次进入，尚未提交搜索或筛选 |
| 关键字模式 | 沿用原关键字列表；不显示本次筛选统计，不应用筛选条件 | 按原搜索提交动作提交非空关键字 |
| 筛选模式 | 当前账本内按已应用筛选展示结果与全量统计 | 在侧栏点击完成，包括显式应用“不限条件” |

输入框仍区分编辑中草稿与已提交关键字。只输入字符、不提交，不改变当前查询；搜索历史的写入时机、数值转换、LIKE 规则及结果排序维持原行为。

关键字模式下筛选按钮禁用并提供“清空关键字后筛选”的可访问说明。通过清空按钮清空已提交关键字，或提交空白关键字后，恢复此前已应用的筛选；此前从未应用筛选则返回初始状态。保留筛选不会导致关键字列表被过滤。

在当前搜索页生命周期内保留已应用条件、模式与列表位置；进入详情或编辑后返回同一搜索页不重置。配置变化恢复状态，真正退出搜索页后重新进入则回到初始状态，不保存为全局默认，也不增加 DataStore 字段。切换账本后必须停止旧账本查询、刷新数据；按当前全局标签与分类模型保留全部已应用条件，仅切换查询账本。禁止从标签名称或当前命中情况推断账本归属，也不新增标签作用域。不允许旧账本统计与新账本列表混排。

## 统计口径

全部金额使用 Long 分求和，复用现有格式化方法显示。

| 记录 | 收入贡献 | 支出贡献 |
| --- | --- | --- |
| 普通收入、退款或报销收入 | finalAmount | 0 |
| 支出 | 0 | finalAmount |
| 转账 | 0 | charges − concessions |
| 平账记录 | 0 | 0 |

结余 = 收入 − 支出。转账本金不参与；转账优惠大于手续费时允许该项为负，不截断为零。退款报销沿用已经计算好的 finalAmount，不重新计算吸收关系，不把 amount 当净额重新求和。

例如不含手续费优惠的 10 月支出 1000 元在 11 月关联报销 800 元后，查询 10 月时该笔净自付为 200 元。此为用户在 grilling 中确认的统计预期；后续关联处理能够改写原支出的依据是 `core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/dao/TransactionDao.kt` 的 `discoverClusterIds`、`recalculateFinalAmountFromCluster`，不是本阶段已执行该案例的声明。

账单明细和命中总笔数包含匹配转账与平账记录；统计按上表排除平账金额。平账类型由既有合成 ID 识别，无对应普通分类行：不限分类时保留，按支出／收入筛选时按其合成类型归属判断，不能因普通分类 INNER JOIN 丢掉。明确选择普通分类时，平账不匹配该普通分类集合。分类选择器不人为新增合成平账选项。界面统计说明注明“净额口径；转账仅计手续费与优惠；平账不计收支”，不承诺统计金额等于列表原始金额之和。

无结果时显示 0 笔、收入／支出／结余为零及空态；查询失败时显示错误和重试，禁止把错误伪装成零结果。筛选切换加载期间不把旧条件的汇总显示为新条件结果。

## 实现边界与由实施者决定的细节

采用现有 `feature/records → core/domain → core/data → core/database` 分层。不另起搜索页面，不改动原关键字 DAO 的语义。

- 模型层表达不可变筛选条件、当前账本与查询版本；界面草稿、分类选择草稿和已应用条件分开。
- 数据库层执行组合过滤。分页列表、命中数量与全量金额聚合使用同一份条件定义，并确保标签匹配不放大记录数。
- SQL 使用绑定参数，不拼接用户提供的关键字、名称或 ID；账本条件不可因空选择或 OR 条件被绕过。
- 大量多选必须按整条 SQL 核算绑定参数预算，计入账本、日期、类型、分类、标签和分页参数。项目现有 `core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/repository/impl/SqlConstants.kt` 的 `SQL_IN_CHUNK_SIZE = 900` 是现有批量查询分块约定，不等于已实测所有目标设备的统一上限。实施计划须在写组合查询前确定可验证的承载策略；不把各组分别小于该值当成整条语句安全的依据。
- 超过实现支持的参数预算时，明确提示、禁止应用并保留此前已应用条件；禁止截断选择、丢弃条件或回落不限。若采用分块方案，必须仍保持唯一账单集合、全局排序、全局分页与准确全量统计，不能把各块的局部分页直接拼接，也不默认把全量命中账单 ID 读入内存规避参数限制。
- 仓库接口新增筛选通路，保留原关键字方法；受影响的测试替身同步实现真实语义。
- ViewModel 将模式、当前账本、条件、数据版本一起驱动查询；使用取消旧请求与结果版本校验，防止迟到结果覆盖新条件；汇总与列表属于同一查询上下文。
- 分类页从已有分类仓库读取真实树与排序，标签从已有仓库读取。条件只保存 ID，名称变化只影响显示。
- 分类或标签被删除时标记不可用，并保持原有约束直到用户明确修改；不能因清理无效 ID 静默扩大查询范围。
- 记录新增、修改、删除以及标签、分类关联变化后，筛选结果与汇总响应现有数据刷新信号。
- 记录、标签、分类和当前账本分别订阅其真实变化源：分类删除、改名和层级调整只更新 `typeDataVersion` 的既有路径不能被仅监听 `recordDataVersion` 漏掉。取消不能被通用异常兜底转成普通查询失败，旧结果不得覆盖新版本。
- 组件沿用 `CbIconButton`、`CbTabRow` 等现有设计系统规则；筛选事件跨多层达到 `CLAUDE.md` 阈值时聚合回调。

由实施计划决定：具体模型和方法名称、SQL 谓词共享组织、动态父组与排除项的内部表示、布局尺寸与抽屉在大屏上的宽度、选中计数的具体文案。上述选择不得改变动态整组、类型联动等已确认语义；需要新增依赖或 schema 迁移时回到设计确认。

当前设计未声称上述新查询、取消机制或状态恢复已经实现；数据库索引是否需要补充需先用真实查询计划和大数据样本核验，不凭空给性能数字。

## 验收矩阵

实施阶段必须从真实筛选入口覆盖以下行为：

1. 同一标签下同时筛选收入与支出；多个标签取任一，重复命中账单只计一次。
2. 多分类、多类型各自取任一，不同维度取交集；同名分类按 ID 区分。
3. 分层分类整组全选、父项直接记账、部分选中、跨类型浏览保留、名称搜索、已选移除、取消返回；选后新增子分类自动纳入、整组排除午餐后新增咖啡仍纳入；主动限制收支类型清除不兼容项并提示。
4. 日期起始日零点与结束日末尾均纳入，结束日次日零点排除；跨月、跨年、本地时区边界与可配置月起始日。
5. 当前账本隔离；同一全局标签跨账本存在账单时，切换后选择保留且只显示新账本记录；未应用条件维持初始态；用户显式应用空组表示不限；非空选择中的全部 ID 失效时不退化为不限；类型与分类冲突时显示零结果和提示。
6. 有关键字时筛选不生效，清空后恢复；金额精确匹配、备注 LIKE 与搜索历史保持原有结果。
7. 超过一页的结果：翻页不漏不重，汇总覆盖全部匹配记录，不随加载页数变化；同一时间戳下翻页顺序稳定。
8. 收入、支出使用 finalAmount；退款、报销、转账本金、手续费、优惠与平账各自验证；包含优惠大于手续费的用例。
9. 快速连续应用条件、修改账单后返回、加载失败与重试、重组、配置变化，不产生条件与结果错配。
10. 手机／平板／折叠屏、长分类名、较多分类与标签、深浅主题及可访问选中状态、返回行为。
11. 标签可见、隐藏、已选后隐藏、已删除四种状态；用户能新选隐藏标签并匹配历史账单，已选隐藏项可见可移除，删除不等同用户主动清空。
12. 分类和标签多选分别及组合跨过既有 900 分块边界，核验实际查询参数策略、重复命中、同时间戳多页和全量统计。明确不支持的规模显示错误、保留原结果条件，不截断或放宽范围。
13. 平账在不限分类及相应收支类型筛选下参与明细和笔数、金额贡献为零；普通分类筛选排除平账。分类版本独立刷新、汇总与分页两种先后返回次序、旧新版本交错均覆盖。
14. 跨日期范围关联报销后历史净额更新；转账 5000 元、手续费 2 元时主金额保持 5000、附注统计支出 2；完全对冲的 800 元报销收入主金额保持 800、附注统计收入 0。该附注不出现在旧关键字模式和其它共享列表入口。
